# 工作流限制的依据

本插件的限制只来自[用户提供的工作流文件及已确认修改](OPERATOR_POLICY.md)和用户后续明确指令。各技能的技术原理、历史案例、工具步骤和取证方法供研究时选用，不另设操作禁令、审批门槛、固定次数或报告接受门槛。

## 用户保留的限制

| 项目 | 规则 | 对应依据 |
|---|---|---|
| 资产 | 指定公司ICP备案资产纳入范围；其他公司或归属未知资产待确认 | 用户文件二.4 |
| 方法 | 正常登录免于 POST 事前审批；其他 POST/PUT/PATCH/DELETE 展示请求并获批；DELETE 只构造不发送 | 用户文件二.3与登录修改 |
| 数据 | 同一漏洞最多 5 条不同真实业务记录；重复不计数；足够证明影响后停止新增读取；自建数据优先 | 用户文件二.5与去重修改 |
| 操作 | 禁止改密码、退出/登出；不做 DoS、不破坏生产、不批量提取敏感数据；禁止恶意攻击、私自植入或保留后门、非法使用病毒 | 用户文件二.5与最新操作红线修改 |
| 时间 | 按站点价值与探索/深挖时间安排；必要时聊天申请加时；时间未完成项进入待续测表并在结束时输出 | 用户文件三、四与续测修改 |
| 正式报告 | 只使用八问；真实请求、可重复、已证明影响；未过八问保留研究笔记 | 用户文件一、二、七与八问修改 |
| 证据 | 允许脱敏并保留复现关系；必要原文按用户文件保存在指定受控位置 | 用户文件七与脱敏修改 |
| 进度 | 重要操作写入 progress.jsonl | 用户文件二.6 |

数据计数的实现见[去重台账](skills/bug-bounty/references/real-records.md)，时间交接见[待续测表](skills/bug-bounty/references/time-deferred-findings.md)。这些资源实现用户规则，不新增限制。各技能引用的固定统计样本、回调方式、测试账号数量、工具和加载顺序均为可选方法；采用能够回答八问的证据即可。
