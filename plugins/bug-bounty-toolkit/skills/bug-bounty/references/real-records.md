# 真实记录去重与 5 条上限

同一漏洞跨接口、账号、工具、重试和后续轮次，最多获取 5 条不同的真实记录；重复数据不增加计数。足够证明影响就停止新增记录读取，不为凑满数量访问。测试账号、自有数据和合成标记优先。不批量提取敏感数据。

## 怎样识别同一条记录

按同一漏洞中的业务对象识别：对象类型＋稳定对象 ID，必要时加入对象所属租户。相同对象通过不同接口返回、字段投影不同、重复请求或字段值更新，仍算同一条；不同对象算不同条，不能以相同响应长度、相同字段结构或一次 HTTP 请求归为一条。无稳定 ID 时使用最小必要的规范化内容指纹；无法可靠去重的内容按新记录计，不猜测重复。响应中的数组、嵌套对象和 WebSocket 消息均按其中的真实业务记录计数，一帧消息可能包含多条记录。

## 执行与恢复

在 `RECON_DIR/record-budget.sqlite` 保存同一漏洞的唯一计数台账。使用[本地计数器](../../../scripts/record_budget.py)的 `plan` 检查已知对象是否会超过上限，`record` 记入实际返回的全部对象身份，`status` 读取状态。输入为规范化对象身份的 JSON 数组，台账只保存 SHA-256 指纹，不保存真实记录内容。它不发送测试请求，也不替代请求审批。

每次新读取前查询剩余额度，限制查询返回量；只能控制分页大小却不能确认服务端遵守时，先用测试数据。实际返回后按业务对象去重并登记，再发下一次请求。意外超量时保留实际数量、停止新增记录读取、记录原因；不把已收到的多余记录隐藏成“只留了五条”。同一漏洞不得改名、另开工具或恢复会话重置计数。并行调用共享同一台账；无法协调返回量时串行读取。

已达到 5 条后，足够证据应收束。确需复现同一已知对象时重复记录不增加计数，但仍受时间、速率、业务影响和已批准方法约束。存在可能返回其他新记录的请求不能以“重复验证”为由放行。

流式返回在达到可用证据时关闭连接。OAST 回调可使用唯一合成标记关联结果；涉及真实业务记录时沿用同一台账。无法限制单帧/单页记录量时使用合成数据验证。

`progress.jsonl` 记录 `finding_id`、`distinct_real_records`、`remaining_record_budget` 和台账位置，不记录原始业务对象身份或真实数据。
